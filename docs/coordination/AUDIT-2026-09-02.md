## C. Custom puzzle image path — corrected handoff

The WebGL picker already works end to end, but its exact boundary matters:

1. `Assets/Plugins/WebGL/Sal0manderBridge.jslib` creates an HTML
   `<input type="file">` accepting PNG, JPEG and WebP.
2. It rejects files over 12 MB, performs no resizing or re-encoding, reads the
   selected file as a temporary base64 data URL, and sends that string to Unity.
3. `PuzzleManager.OnWebCustomImageSelected` decodes the bytes into a Unity
   texture.
4. Unity stores the raw image bytes as
   `persistentDataPath/CustomPuzzles/custom_saved.png` and records only
   `imagePresetIndex = -1` in the activity.

**Correction:** the puzzle photo is not embedded as base64 inside the activity
JSON. Base64 is the browser-to-Unity transport. The stored image is still
device-local in WebGL persistence, so it is not a class-shareable storage model.

The web repo already contains `optimizeImages`, which caps the longest edge at
2048 px and encodes WebP at 0.8 quality when that produces a smaller file. It
wraps the future media provider, but custom uploads remain feature-gated and it
is not currently wired into Unity's HTML picker.

### Handoff consequence

Moving authoring to the website can reuse the browser's native picker, but it
still requires an explicit integration:

`browser picker → optimizeImages → media provider/backend → durable URL → Unity`

`MediaType.WebUrl` exists in the Unity data model, but its presence alone does
not make custom puzzle images remotely stored or shareable.
