Do not guess between them. The page says which.

**#70 is one school, not universal compatibility.** The wider gate — Chromebook,
managed iPad, Windows Edge, several networks — is a separate, later matrix. Run
one first; a single real result beats a planned matrix.

### The unclaimed item that matters most: a custom domain

Implied repeatedly all evening, owned by nobody, and it fixes four separate
problems at once:

1. **Filter risk.** `*.github.io` is a shared host; filters categorise the whole
   domain, so the site is judged by its neighbours. A first-party domain is
   judged on its own.
2. **The homoglyph.** `SAL0MANder` has a zero in it. A student typing it from
   paper types `SALOMANDER` and gets nothing. `play.sal0mander.com/a/HOOPS`
   removes the failure entirely.
3. **Case sensitivity.** GitHub Pages paths are case-sensitive; `sal0mander-web`
   does not resolve. Second silent failure, same outcome.
4. **Permanence.** TPT can deactivate a product whose link stops resolving, and
   printables cannot be recalled. The current URL is tied to one GitHub account
   name and one repository name.

A purchase plus DNS plus a Pages setting. Owner-only, and the highest leverage
item on this page.

## 2. Track B — Teacher Studio

Design is settled enough to build. The corrections that became canonical:

- `/play/*` and `/studio/*` stay separable at the URL level, decided **before**
  the first handout ships. TPT forbids linking to a site that sells; Studio is
  the commercial side. Printables cannot be recalled.
- Publish readiness must be **executable proof** — question → correct answer →
  intended piece unlocks → activity completes — not a checkbox that ticks when
  Preview was opened. A decorative checkmark makes the whole gate a suggestion,
  which is the exact defect class this repo found eight times on 2026-08-25.
- Completability is a **shared schema invariant**, not a Studio-only check.
  Anything that writes an activity another way must be unable to produce an
  uncompletable one.
- Preview needs an **isolated identity**. Guest identity here is device-local
  (`identity.guestToken`); a teacher testing on their own machine writes where a
  student would, so the fifth test run looks like a returning student.
- **Reuse `CompanionLayout`** for the collapsible preview. It already does the
  42/58 split, persisted collapse, bottom sheet below 60rem, and reveal on the
  rising edge only. A second implementation drifts from the first.
- Platform vendors stay behind interfaces (`AuthPort`, `ActivityDraftRepository`,
  `MediaRepository`, `PreviewSession`, `PublishService`) with local adapters
  first, so the UX proves itself before a provider defines the architecture.
- A **separate authoring contract**, not accretion onto frozen `v1`.

**Metric, decomposed** — one five-minute number hides four problems:
import < 60s · review flagged < 90s · puzzle config < 45s · verified preview
cycle < 60s · publish and retrieve QR < 30s.

Codex has the first slice on an isolated branch from `origin/main`.

## 3. Track C — TPT packages

Rules are read and recorded in `TPT-RULES.md`. Assets exist. What is genuinely
missing:

### Not yet claimed by anyone

- **Rights QA on every question.** TPT requires you own or license what you sell.
  A library of verified questions that cannot legally ship is a failure that only
  appears after the work is done. Classify each source *before* extracting:
  original / licensed / public domain / no.
- **Answer keys verified on the printables.** A wrong key in a free handout costs
  more trust than no handout. These are the lead magnet; they are the first thing
  a teacher judges.
- **Load time measured on a phone, on a school network.** ~30 MB gzipped, once
  per device. A class of thirty on first load is ~900 MB across a shared network.
  Never measured. This is the difference between outcome 1 and outcome 3 above.
- **The end state.** What a student sees when the activity completes. It decides
  whether the demo feels finished or truncated, and no one has specified it.

### Delivery ladder — website first, printable always

| Path | Friction | Use |
| --- | --- | --- |
| QR / short link on a custom domain | lowest | normal access |
| Installable offline PWA | low | Chromebooks, iPads, poor Wi-Fi |
| Downloadable activity package | medium | LMS, email, USB |
| Standalone desktop demo | higher | conferences, blocked networks |
| Printable pixel-art handout | none | universal fallback |

Every format must derive from the **same immutable activity version**, or the
printed key and the played answers will drift apart. Each export shows a real
status — Ready / Generating / Failed with retry — and never a decorative check.

**Managed Chromebooks and iPads often forbid downloaded applications, so the
printable is the only path that always works.** That is why it is the lead magnet
and not an afterthought.

## 5. The sequencing argument, stated once

Teacher Studio is a large build against zero validated demand. Nobody has scanned
a handout QR yet.

If #70 fails because the school filters `github.io`, Studio does not matter yet —
no teacher reaches anything built. If it succeeds, Studio gets designed against
evidence instead of a wireframe.

**Run the thirty-second test before the five-minute build.** Not instead of it.
Before it.
